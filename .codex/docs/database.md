# DB 설계

Room을 통해 차량 내부 SQLite에 저장합니다. 다음은 논리 설계이며 컬럼 타입·인덱스·마이그레이션은 구현 시 구체화합니다.

| 테이블 | 주요 데이터 |
|---|---|
| trips | 여행 ID, 시작·종료 시각 및 누적거리, 상태 |
| segments | 여행 ID, 순번, 시작·종료 거리, 연비 원본값·단위·집계 범위, 시각, 출처 |
| fuel_prices | 유종, 원/L 가격, 기준일, 출처 |
| settlements | 여행 ID, 총액, 인원수, 계산 방식, 확정 시각 |
| settlement_items | 정산 ID, 구간별 적용 거리·연비·단가·비용 |
| settlement_shares | 정산 ID, 참여자 순번 또는 이름, 정수 원 단위 분담액 |

## 관계 및 일관성

- 여행 하나에 여러 구간이 연결됩니다. 구간 순번은 여행 안에서 유일해야 합니다.
- 확정 정산 하나에 여러 계산 항목과 분담액이 연결됩니다.
- 정산은 계산 당시 입력값을 스냅샷으로 보존하고 하나의 트랜잭션으로 저장합니다.
- 중복 구간 이벤트와 중복 확정 요청을 식별해 중복 저장을 막습니다.
- 실패한 조회를 0으로 저장하지 않습니다. 누락된 구간을 숨긴 채 전체 비용으로 확정하지 않습니다.
- 앱 재실행 시 진행 중 여행을 복구합니다. 화면 메모리를 영속 데이터로 간주하지 않습니다.
- Room 스키마 이력을 app/schemas에 관리하고 기존 데이터를 유지하는 마이그레이션을 작성합니다.

계산 정책은 [아키텍처](architecture.md), 검증은 [테스트 전략](testing.md)을 따릅니다.
