## 2. 코드 보완 (결정은 났고 구현이 비어 있는 것)

- **구간 사용량 단위 저장**: 지금은 단위(L/kWh)를 결과에 저장하지 않아 전기차도 화면에 "L"처럼 보일 수 있다. `FuelIntervalResult`와 `payment_settlement_fuel_intervals`에 단위 컬럼이 필요하다(스키마 변경이므로 v5가 배포되기 전에 넣는 것이 안전하다).
- **정산 대기 목록 합계**: `ObserveSettlementListUseCase`의 대기 합계가 입력 비용 합이다. v2 여행은 실제 계산값과 다르므로 v2는 합계를 숨기거나 "종료 후 계산"으로 표시한다.
- **기록 공백 표시**: 앱이 꺼져 있던 구간을 "기록 공백"으로 보여 주기로 했으나 표시가 없다. 스냅샷 간격이 길면 표시한다.
- **STOP 경계 표시**: `STOP`·`PARKED` 스냅샷은 저장만 하고 화면에 보이지 않는다.
- **주유 감지 지연**: 연료 %는 60초 폴링이라 최대 약 60초 늦게 감지한다. 결정 문서는 `registerFuelPercent` 리스너를 적었다. 폴링을 유지할지 리스너를 추가할지 정한다(이벤트가 오는지는 실차 확인이 필요하다).
- **경고문 문구**: 결정 문서의 초안("주유한 순서대로 입력…")과 구현 문구가 다르다. 하나로 맞춘다.
- **시작 측정 실패**: 첫 읽기에 실패하면 START 스냅샷이 없고 구간 0의 시작이 비어 "측정 없음"으로 제외된다. 재시도 시점과 안내를 정한다.
- **하이브리드**: 연료 % 우선, 없으면 배터리 순으로 읽는다. 하이브리드 차량의 단위·단가 처리는 정하지 않았다.
- 패키지명 `com.gatita`는 임시다. 제출 전에 정한다.

## 3. 확인이 필요한 것 (공모전·SDK 담당자 문의 또는 실차)

- 시동 ON/OFF 이벤트 공식 수신 방법, 시동 후 앱 자동 실행 여부, 백그라운드·포그라운드 서비스 허용 여부 → 시동 OFF 직전 공백(마지막 60초 + 앱이 죽어 있는 동안)의 크기를 결정한다.
- "마지막 주유 이후" 연비·거리의 초기화 시점(시동 사이클 포함), 공회전 연료 포함 여부, 에뮬레이터에서 지원하지 않는 연비 API의 실차 지원.
- 연료 % 갱신 주기·정밀도(5% 임계값의 적정성), 하이브리드의 `Fuel`/`EvBattery` 선택.
- 기어 API(숨김·deprecated)의 공식 대체(Google `GEAR_SELECTION`) 사용법. 현재 P단 감지는 deprecated API의 리스너다.
- 실차 또는 속성값을 주입할 수 있는 테스트 환경.
- 위젯: Pleos Connect에서 앱 위젯 제공 가능 여부, 방식, 위젯에서 차량 데이터 읽기 허용 여부. 가능하면 "진행 중 여행·현재 거리" 같은 읽기 전용 소형 위젯부터 검토한다. 정산 확정·비용 입력은 위젯에 넣지 않는다.

## 4. 사용자 결정 대기

- 연비를 못 받은 구간: 현재 구현은 **제외하고 "유류비 미포함"으로 표시**한다(평균 대체·거리 비례 배분 없음). decisions.md의 "미확정" 제안(거리 비례 배분)과 다르므로 이 방식으로 확정할지 정한다.
- 전기차 단가 단위(kWh당)와 `calculationVersion` 이름(`fuel-segments-v2` 유지 여부).
- 실차 검증을 제출 전에 못 할 때 발표·제출물에서 무엇을 "검증됨"으로 말할지(샘플·에뮬레이터 값은 실차 검증이 아니다).
