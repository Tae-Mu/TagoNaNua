# 같이타 기획

## 목적

친구 여행이나 모임에서 한 차로 이동하며 쓴 **실제 결제 금액**(주유·주차·톨비·기타)을 한 곳에 모아 인원별로 나눕니다. 실제 결제나 송금은 앱이 처리하지 않으며 초기 범위에 포함하지 않습니다.

> 2026-11-09 개정: 이전의 "주행거리 × 연비 × 유가로 예상 유류비 계산" 방식은 현재 제품이 아닙니다. 최신 HTML 기준([html-api-spec](html-api-spec.md))의 결제액 방식으로 전환했습니다. 근거는 [결정 기록](decisions.md)을 봅니다.

## 사용자 흐름

1. 여행 시작: 이름과 인원을 정하고 시작 주행거리·시각을 저장합니다.
2. 기록: 주행 구간을 저장합니다(지원 환경에서는 시동 OFF 활용, 불가능하면 정차 후 수동). 구간·거리는 기록 정보이며 정산 금액에 곱하지 않습니다.
3. 비용 등록: 주유·주차·톨비·기타(FUEL/PARKING/TOLL/OTHER)를 실제 결제한 금액으로 입력합니다. 주유는 리터당 단가와 주유일을 함께 받으며 주유량(L)은 금액÷단가로 **표시만** 합니다.
4. 여행 종료.
5. 정산: 비용별 정산 포함 여부, 인원, 운전자 포함/제외를 정합니다. 총액은 **포함된 비용의 실제 입력 금액 합계**입니다.
6. 확정 및 공유: 비용 전체(제외 항목 포함)·인원·분담액·표시 이름을 복사해 고정하고 정산 요약 텍스트 QR을 표시합니다.

## 확정된 정책

- 정산 총액 = `included=true`인 비용 금액의 합. 거리·연비·유가로 추정한 값을 더하지 않습니다.
- 주유량(L)은 표시용 파생값입니다. 정산 금액에 다시 곱하지 않습니다.
- 운전자 포함 ON이면 전체 인원, OFF이면 운전자는 0원이고 동승자만 분담합니다. 인원이 1명이면 ON으로 고정합니다.
- 분담액은 정수 원이며 나머지는 대상자 순서대로 1원씩 배분해 합계가 총액과 같습니다. 예: 3,685원 / 4명 → 922·921·921·921원.
- 비용 입력 범위: 금액 1~10,000,000원, 인원 1~8명.
- 확정된 정산은 수정할 수 없습니다. 비용만 있는 0km 여행도 정산할 수 있고, 측정이 없으면 0이 아니라 "측정 없음"으로 표시합니다.
- 구간·비용·기록 거리가 모두 없는 진행 중 여행은 마칠 수 없으므로, 여행 화면의 "빈 여행 닫기"로 확인 후 삭제하고 홈으로 돌아갑니다. 하나라도 기록이 있거나 완료·확정된 여행은 삭제하지 않습니다(일반 여행 삭제는 미구현).
- 옛 추정 방식(v1)으로 확정한 정산은 삭제하지 않고 "옛 추정 정산"으로 구분해 읽기 전용으로 보여줍니다.

## 첫 버전

Kotlin·Compose·Room 기반 오프라인 앱입니다. 샘플·수동 입력으로 전체 흐름을 검증한 뒤 실제 Pleos 데이터를 연결합니다. 실제 데이터와 샘플·수동 출처를 구분합니다. 회원, 서버, 클라우드 동기화, 자동 유가·카드·하이패스 결제 수집은 초기 범위에서 제외합니다.

## 구현 상태 구분

구현 여부는 README.md가 기준입니다. 이 문서는 요구사항입니다. 아래는 [html-api-spec](html-api-spec.md)에 있지만 **아직 구현하지 않은** 항목입니다.

- 설정 화면(표시 이름·새 여행 정산 기본값·화면 모드)과 설정 초기화
- 여행 잠시 멈춤/이어가기(PAUSED) 상태
- 구간·비용·기록 거리가 있는 여행을 포함한 일반 여행 삭제(완료·확정 여행 삭제 포함)
- 차량 PARKED 상태 확인을 통한 편집 차단
- 같은 요청을 식별하는 별도 명령 영수증(command_receipts) 테이블

## 검증 과제

연비 집계 기준, 시동 OFF 후 저장 가능 여부, 재시동 구독 복구, 기록 시간의 정의(주행 시간/시동 시간/경과 시간), 휴대폰 QR 리더의 텍스트 표시 방식은 실차·실기기 검증이 필요합니다.
