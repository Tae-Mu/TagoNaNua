# 같이타 기획

## 목적

친구 여행이나 모임에서 한 차로 이동하며 쓴 **실제 결제 금액**(주유·주차·톨비·기타)을 한 곳에 모아 인원별로 나눕니다. 실제 결제나 송금은 앱이 처리하지 않으며 초기 범위에 포함하지 않습니다.

> 2026-11-09 개정: 이전의 "주행거리 × 연비 × 유가로 예상 유류비 계산" 방식은 현재 제품이 아닙니다. 최신 HTML 기준([html-api-spec](html-api-spec.md))의 결제액 방식으로 전환했습니다. 근거는 [결정 기록](decisions.md)을 봅니다.
>
> 2026-11-12 재개정(결정 확정, 구현 진행 중): 정산 방식이 **구간별 유류비 방식(`fuel-segments-v2`)**으로 다시 바뀌었습니다. 총액 = Σ(주유 구간 사용량 × 입력 단가) + 기타 비용(PARKING/TOLL/OTHER 입력 금액). 이전 "예상 유류비"와 달리 단가는 사용자가 입력한 주유 단가이고, 사용량은 차량이 보고한 "마지막 주유 이후" 누적 연비의 측정값 차이로 구합니다. 현재 앱의 저장·화면은 아직 결제액 방식입니다. 아래 "확정된 정책"은 현재 앱(`payments-v1`) 기준이며, 새 방식의 상세 규칙은 [결정 기록](decisions.md)의 2026-11-12 항목이 우선합니다.

## 사용자 흐름

1. 여행 시작: 이름과 인원을 정하고 SDK에서 받은 시작 주행거리·시각을 저장합니다. 거리 직접 입력은 제공하지 않습니다.
2. 기록: SDK에서 받은 주행 구간을 저장하는 흐름입니다. SDK 미연결을 사용자 거리 입력으로 대체하지 않습니다. 구간·거리는 기록 정보이며 정산 금액에 곱하지 않습니다.
3. 비용 등록: 주유·주차·톨비·기타(FUEL/PARKING/TOLL/OTHER)를 실제 결제한 금액으로 입력합니다. 주유는 리터당 단가와 주유일을 함께 받으며 주유량(L)은 금액÷단가로 **표시만** 합니다.
4. 여행 종료.
5. 정산: 비용별 정산 포함 여부, 인원, 운전자 포함/제외를 정합니다. 총액은 **포함된 비용의 실제 입력 금액 합계**입니다.
6. 확정 및 공유: 비용 전체(제외 항목 포함)·인원·분담액·표시 이름을 복사해 고정하고 정산 요약 텍스트 QR을 표시합니다.

## 확정된 정책

- 정산 총액 = `included=true`인 비용 금액의 합. 거리·연비·유가로 추정한 값을 더하지 않습니다.
- 주유량(L)은 표시용 파생값입니다. 정산 금액에 다시 곱하지 않습니다.
- 운전자 포함 ON이면 전체 인원, OFF이면 운전자는 0원이고 동승자만 분담합니다. 인원이 1명이면 ON으로 고정합니다.
- 분담액은 정수 원이며 나머지는 대상자 순서대로 1원씩 배분해 합계가 총액과 같습니다. 예: 3,685원 / 4명 → 922·921·921·921원.
- 비용 입력 범위: 금액 1~10,000,000원, 인원 1~8명.
- 확정된 정산은 수정할 수 없습니다. 비용만 있는 0km 여행도 정산할 수 있고, 측정이 없으면 0이 아니라 "측정 없음"으로 표시합니다.
- 구간·비용·기록 거리가 모두 없는 진행 중 여행은 마칠 수 없으므로, 여행 화면의 "빈 여행 닫기"로 확인 후 삭제하고 홈으로 돌아갑니다. 하나라도 기록이 있거나 완료·확정된 여행은 삭제하지 않습니다(완료 여행은 목록에서 숨길 수 있으나 원본 영구 삭제는 제공하지 않음).
- 옛 추정 방식(v1)으로 확정한 정산은 삭제하지 않고 "옛 추정 정산"으로 구분해 읽기 전용으로 보여줍니다.

## 구간별 유류비 방식 요약 (`fuel-segments-v2`, 2026-11-12 확정, 계산기·수집·저장·화면 작성, 앱 빌드·실차 미검증)

- 여행은 "주유 구간"으로 나뉩니다. 구간 0은 여행 시작~첫 주유 직전, 이후 구간은 주유 직후~다음 주유 직전(또는 종료)입니다. 단가가 바뀌는 곳은 주유뿐이기 때문입니다.
- 단가: 구간 0과 1은 첫 주유 비용의 L당 단가, 구간 k는 k번째 주유 비용의 단가. 주유가 없으면 직접 입력한 단가를 쓰고, 입력하지 않으면 유류비를 포함하지 않되 정산은 막지 않습니다("유류비 미포함" 표시).
- 주유 감지: 연료 %가 5% 이상 오르면 주유 이벤트입니다. 주유 비용은 입력한 순서대로 감지된 주유와 짝이 됩니다. 감지된 주유 수와 FUEL 비용 수가 다르면 여행을 종료할 수 없으며, 감지 오류는 "주유 아님"(이벤트 제외)·"감지 안 됨"(비용을 짝짓기에서 제외)으로 해소합니다.
- 구간 경계: 여행 시작·종료, 주유, P단 진입 후 거리 변화 없이 2분 이상 정차(표시용 하위 구간).
- 사용량은 내연 L/100km, 전기 km/kWh의 누적 연비 측정값 차이로 구합니다. 측정이 없는 구간은 0이나 평균으로 메우지 않고 제외·표시합니다. 반올림은 합계에서 한 번만 HALF_UP입니다.
- 연료 사용량·단가는 주유 폼의 L당 단가 입력을 씁니다. SDK 연료량(L)이나 탱크 용량은 쓰지 않습니다.
- **실차 미검증**: 연비 API 값 수신, 공회전 연료 포함 여부, 시동 사이클 중 앱 실행 지속은 확인되지 않았습니다. 앱이 꺼진 동안의 기록은 보장하지 않으며 복원할 수 없는 구간은 기록 공백으로 표시하는 방침입니다.

## 첫 버전

Kotlin·Compose·Room 기반 오프라인 앱입니다. 거리·주행 정보는 사용자 입력이 아니라 Pleos SDK 수신값이며, 현재 계기판 주행거리 읽기만 연결되어 있습니다. 실제 데이터와 샘플·수동(기존 기록) 출처를 구분합니다. 회원, 서버, 클라우드 동기화, 자동 유가·카드·하이패스 결제 수집은 초기 범위에서 제외합니다.

## 구현 상태 구분 (2026-11-10)

현재 실제 앱은 여행·비용·정산·공유·내역과 아래 기능을 연결했다. 거리 수동 입력은 제거했으며, 새 여행은 PleosVehicleDataSource가 주행거리를 읽어야 시작된다(읽기 실패 시 시작 보류). 화면·버튼·디자인 기준은 [화면·퍼블리싱 명세](publishing.md), 함수 매핑은 [API 명세 0장](html-api-spec.md)을 따른다.

- 설정(표시 이름·새 여행 정산 기본값·화면 모드) 저장 및 초기화.
- 수동 일시정지/재개. IN_PROGRESS는 유지하며 trip_sessions.pausedAt으로 구분한다.
- 완료·확정 여행의 목록 숨김. 원본과 확정 스냅샷을 영구 삭제하지 않는다.
- 태블릿 UI 재정렬: 준비/설정 2열, 가로 구간 카드, 일시정지/완료, 비용 폼, 내역 통계, 정산 액션.

남은 범위: 실제 차량 PARKED 편집 차단·Pleos/시동 OFF 자동 기록, 범용 command_receipts, 완료/확정 원본 영구 삭제. 실제 송금·자동 비용 수집은 범위 밖이다.

## 검증 과제

연비 집계 기준, 시동 OFF 후 저장 가능 여부, 재시동 구독 복구, 기록 시간의 정의(주행 시간/시동 시간/경과 시간), 휴대폰 QR 리더의 텍스트 표시 방식은 실차·실기기 검증이 필요합니다.
