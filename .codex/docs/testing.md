# 테스트 전략

Kotlin 앱은 JUnit 기반 단위 테스트, Room 기기 테스트, Compose UI 검증으로 나눕니다. Jest는 도입하지 않습니다. 테스트 도구의 구체적인 버전은 Gradle 설정 시 확정합니다.

| 범위 | 핵심 사례 |
|---|---|
| 정산 계산 | 구간별 합산, 누적 평균 사용량 차이, fallback 표시 |
| 금액 | 중간 반올림 없음, 최종 HALF_UP, 3,685원/4명 → 922·921·921·921원 |
| 불변식 | 분담액 합계 = 총액, 모든 분담액은 정수 원 단위 |
| 입력 | 0 이하 연비, 음수 거리, 감소한 누적거리, 잘못된 가격·인원 거부 |
| Room | 여행 복구, 트랜잭션 원자성, 중복 구간·정산 방지, 마이그레이션 |
| 차량 | 조회 실패·시간 초과·연결 복구·중복 OFF·단위와 집계 기준 |
| UI | 빈 상태, 로딩, 오류, 긴 문구, 중복 조작, 재진입 |
| QR | 한글 인코딩, 실제 리더에서 읽기, 공유 정보 범위 |

## 실행 및 보고

빌드 설정이 준비되면 실제 Gradle 작업을 확인해 단위 테스트·Lint·debug 빌드를 CI에 연결합니다. 기기 테스트는 환경을 확보한 뒤 실행합니다. 실행하지 못한 검증은 이유를 명시하고 샘플·에뮬레이터·실차 결과를 구분합니다.
