# 테스트 전략

Kotlin 앱은 JUnit 기반 단위 테스트, Room 기기 테스트, Compose UI 검증으로 나눕니다. Jest는 도입하지 않습니다.

## 현재 테스트 상태 (2026-11-09)

결제액 방식 전환 이후 **테스트를 실행하지 않았고 새로 추가하지도 않았습니다.** 사용자가 테스트 불필요를 명시적으로 요청했습니다. 저장소에 남아 있는 테스트 코드는 이전 구현 기준이며 새 구현에서의 통과·컴파일 여부는 확인되지 않았습니다.

- 이전(추정 유류비) 버전의 결과 — 단위 107/107, 기기(API 35 ARM 에뮬레이터) 21/21 — 는 **새 구현의 결과가 아닙니다.** 새 구현의 통과를 의미하지 않으며 현재 근거로 쓰지 않습니다.
- 새 구현에서 확인된 것은 `./gradlew :app:assembleDebug` 성공과 Room 스키마 v2 생성뿐입니다. Lint, 단위·기기 테스트, 마이그레이션 실행, 수동 QA, 실차 검증은 하지 않았습니다.

## 필요한 검증 (미실행)

| 범위 | 핵심 사례 |
|---|---|
| 비용 합계 | 포함/제외 합계, 종류별 소계(포함 여부 무관), Long 오버플로 거부, 포함 비용 0건 확정 차단 |
| 분담 | 운전자 포함/제외, 1명 정규화, 1~8명, 나머지 순서 배분, 3,685원/4명 → 922·921·921·921원, 55,400원/4명 제외 → 0·18,467·18,467·18,466원, 합계 = 총액 |
| 주유량 | 금액÷단가 소수 3자리 HALF_UP이 표시에만 쓰이고 총액에 영향 없음 |
| 입력 | 금액 0/음수/10,000,001, 단가 0·10,000·소수 3자리, 없는 주유일, 인원 0·9명, 종류 변경 시 필드 정리 |
| 확정 | 스냅샷에 제외 비용 포함, stale revision 거부, 이중 확정·이중 비용 등록(requestId), 확정 후 수정 차단(UseCase와 DB 트리거), 트랜잭션 롤백 |
| 측정 | 거리·연비 없음/부분 측정이 확정을 막지 않고 0으로 대체되지 않음, 비용만 있는 0km 여행 |
| Room | 진행 중 여행 1건 제한, 앱 재실행 복구, 손상·실패 시 기존 기록 보존 |
| 마이그레이션 | v1→v2 데이터 보존(여행·구간·유가·정산·분담액), v1 여행 보정값, v1 정산이 legacy로 표시, 새 테이블·인덱스·트리거가 엔티티와 일치 |
| 차량 | 조회 실패·시간 초과·연결 복구·중복 OFF·단위와 집계 기준 (SDK 연동 후) |
| UI | 빈 상태, 로딩, 오류, 긴 문구·큰 금액, 중복 조작, 재진입, 옛 추정 정산 구분 표시 |
| QR | 한글 인코딩, 실제 리더에서 읽기, 공유 정보 범위 |

## 실행 및 보고

테스트는 사용자가 요청할 때 실행합니다. 실행하지 못한 검증은 이유를 명시하고 샘플·에뮬레이터·실차 결과를 구분합니다. 이전 버전 결과를 새 구현의 결과로 보고하지 않습니다. 빌드 성공을 테스트 통과로 표현하지 않습니다.
