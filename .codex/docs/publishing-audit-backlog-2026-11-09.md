# TAGO 퍼블리싱 전반 QA와 개선 목록

검수일: 2026-11-09(KST). 아래 발견 사항은 최초 검수 당시 기록이다. 이후 사용자 요청에 따라 Compose 소스를 수정했으며, 반영 현황은 문서 하단에 기록했다. HTML 원본은 변경하지 않았다.

## 판단

화면 구성과 기본 이동을 검토할 수 있는 단계지만, HTML 기준 퍼블리싱 완료로 보기는 어렵다. 우선 해결할 부분은 **야간 가독성, 확정/미확정 화면 분리, 실제 태블릿 높이에서의 행동 버튼 배치, 샘플 상태 간 일관성**이다. 앞선 16개 경로 통과는 주요 화면 이동 확인이며 전체 디자인 일치·모든 상태 통과를 의미하지 않는다.

## 검수 방법과 범위

- Android: TAGO_Tablet / emulator-5556, 설치된 `com.gatita.publishing`, 2560×1600px / 320dpi(1280×800dp). 다른 에뮬레이터는 조작하지 않았다.
- ADB로 화면 선택, 탭, 스크롤, 상태 전환, 접근성 트리와 스크린샷을 수집했다. 홈·출발 준비·기록·복원·완료·비용 내역·비용 종류·주유·기타 비용·정산 목록·상세·여행 내역·설정 **13개 기본 화면**을 열어 확인했다.
- 추가 검수: 야간 홈, 확정 여행에서 상세 진입, 정산/여행 내역 빈 상태, 주유 오류/로딩, 주행 기록의 행동 버튼.
- HTML: `HD 프로젝트/preview`와 실행 중인 localhost. 복원·기록·비용 종류·주유·설정·여행 내역·확정 상세를 직접 열어 DOM/화면을 비교했다. 비교용 브라우저 크기는 1280×718로 설정했다.
- Android 상태 표시줄·작업표시줄·퍼블리싱 툴바가 차지하는 높이는 웹과 다르다. 이미지를 일괄 확대해 맞추는 방식이 아니라 사용 가능한 영역과 정보 위계로 판단했다. 스크롤 위치가 다른 캡처도 있으므로 자동 픽셀 일치율은 산정하지 않는다.
- 출발 모션은 앞선 같은 APK의 시간별 캡처와 소스 대조를 참고한 항목으로 구분한다. 이번 검수에서 프레임 성능 측정은 하지 않았다.
- 실제 저장·차량 연결·정산 계산·송금은 범위 밖이다. 샘플 데이터 미연동 자체를 제품 버그로 세지 않고, **시안에서도 서로 모순되는 표현**을 개선 대상으로 삼았다.

## 유지할 부분과 확인된 동작

- TAGO 로고, 차량 이미지, 블루/네이비 기조, 비용별 선형 아이콘은 기본 방향을 유지해도 된다.
- 출발 준비의 2열 구성과 기록/복원/완료의 정보 그룹은 식별 가능하다.
- 여행 내역 빈 상태는 요약·건수·목록이 모두 0으로 일치한다.
- 주행 샘플에서 기록 하단 비용 추가/종료 버튼은 비활성으로 표시된다. 이는 실차 제한 검증이 아니다.
- 야간/주간 적용 후 기본 주간 홈으로 복구했고, HTML 비교용 브라우저 크기도 복구했다.

## 우선순위

- **P1**: 다음 퍼블리싱 작업에서 먼저 해결. 상태 오인·읽기 어려움·주요 행동 접근에 영향.
- **P2**: HTML과의 구조/상태/상호작용 차이. 퍼블리싱 완료 전 해결.
- **P3**: 시각적 완성도와 세부 모션 정리.
- 증거 표기: **실행**은 실제 화면/조작 확인, **코드**는 코드와 HTML 대조로 확인. 재현 경로도 함께 기재한다.
