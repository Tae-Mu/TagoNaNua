# TAGO 실제 앱 화면·퍼블리싱 명세

갱신: 2026-11-10. 기존 HTML(`HD 프로젝트/preview`)을 기준으로 실제 앱 `com.gatita`에 적용한 화면과 연결 동작을 기록한다. **Kotlin·Jetpack Compose·Room 기반 오프라인 앱**이며, 샘플 퍼블리싱과 실제 저장 기능을 구분한다. API·함수는 [내부 기능 명세](html-api-spec.md), 테이블은 [DB 설계](database.md)를 따른다.

## 최신 정책 보정: 차량 거리 입력 제거

2026-11-10 사용자 확인: 거리·주행 정보는 사용자 입력이 아니라 차량 SDK 수신 데이터다. 출발 계기판·구간 종료 거리·연비 수동 입력 및 구간 저장 버튼을 제품 화면에서 제거했다. HomeViewModel은 VehicleDataSource.readSnapshot() 성공값으로 여행을 시작하며 SAMPLE/MANUAL 값은 실제 시작에 사용하지 않는다. 실패·10초 응답 시간 초과 시 안내하고 여행을 생성하지 않는다. 임의의 0km도 저장하지 않는다.

`AppContainer`는 `PleosVehicleDataSource`(계기판 주행거리만)를 사용한다. 읽기 실패·응답 시간 초과 시 **새 여행 시작은 보류**된다(2026-11-12 갱신: 이전의 UnavailableVehicleDataSource는 삭제). Android Studio에서의 동작은 사용자가 확인했으나 범위는 기록하지 않았고 실차는 미확인이다. 기존 여행/비용/정산은 유지한다. 실제 주행 이벤트 구독·자동 구간 저장은 아직 구현되지 않았다. 아래 검증 이력의 수동 구간 QA는 이 보정 전 기록이다.

## 1. 적용 범위와 구현 위치

| 구분 | 구현 위치 | 현재 역할 |
|---|---|---|
| 실제 앱 진입·내비게이션 | `navigation/AppNavHost.kt`, `ConnectedShell.kt` | 실제 ViewModel 연결. 여행/정산/여행 내역/설정 메뉴 |
| 공통 UI | `core/ui/component/Components.kt`, `FormComponents.kt`, `PublishingComponents.kt` | 헤더, 패널, 버튼, 입력, 지표, 오류·빈 상태, 로고 |
| 디자인 토큰 | `core/ui/theme/TagoTheme.kt` | SUIT, 주간/야간 색상, 시스템 바 대비 |
| 실제 화면 | `feature/home`, `trip`, `cost`, `settlement`, `history`, `share`, `settings` | Room 데이터 조회 및 UseCase 명령 연결 |
| 시안·공유 UI | `feature/publishing`, `navigation/PublishingApp.kt` | 독립 샘플 화면. 출발 로고 전환·날짜 선택·비용 아이콘 등 일부 UI는 실제 앱에서도 사용 |
| 리소스 | `res`, `assets/asset-notices.txt` | 차량 예시 이미지, SUIT, TAGO·메뉴·비용 벡터 아이콘, 라이선스 |

이전 퍼블리싱 문서의 “데이터를 저장하지 않는다”는 `PublishingApp` 샘플에만 해당한다. 현재 실제 앱의 여행·구간·비용·확정 정산·설정은 Room에 저장된다. 원본 HTML과 샘플 시안은 보존한다.

## 2. 화면 계층과 이동

- `home`: 홈과 출발 준비는 같은 경로 안의 UI 상태다. 여행 저장 성공 후 출발 로고 안내를 표시하고 `trip/{tripId}`로 이동한다.
- `trip/{tripId}`: 기록/일시정지/비용 목록/여행 완료 안내를 상태에 따라 표시한다. 별도 PAUSED 경로나 상태 enum은 없다.
- `cost/{tripId}/{costId}`: 비용 종류 선택 및 추가/수정. 신규는 `UNSAVED_ID`. 저장 성공 시 호출 화면으로 pop한다. 기록에서 추가하면 기록으로, 비용 목록에서 수정하면 해당 목록으로 복귀한다.
- `settlements`: 미정산·확정 정산 목록. `settlement/{tripId}`는 정산 확인, `result/{tripId}`는 저장된 확정 결과다.
- `history`: 월별 여행 목록과 필터. 기록 중 → 여행, 완료 → 정산 확인, 확정 → 결과 화면으로 이동한다.
- `settings`: 실제 저장 설정. 저장된 화면 모드를 앱 루트에 적용한다.

### 상태·예외 처리

- 로딩/오류/빈 상태를 구분하고 조회 실패 시 재시도를 제공한다. 조회 실패를 0원이나 빈 목록 저장으로 처리하지 않는다.
- 시작·비용 저장·정산 확정 등 처리 중 중복 명령을 제한한다. 실패 시 폼과 오류를 유지한다.
- 오래된 비용 수정/확정은 revision 충돌을 처리한다. 비용 폼은 최신 내용 다시 불러오기를 제공한다.
- 구간이 없으면 거리는 미기록이다. 수동 구간 시간은 **경과 시간**이며 실제 주행 시간으로 표현하지 않는다.
- 구간·거리·비용이 모두 없는 진행 중 여행은 별도 빈 여행 닫기로만 폐기할 수 있다.
- 운전자 제외 시 동승자만 분담하고 운전자는 0원. 1명 여행은 포함 강제. 확정 후 비용·정책·표시 이름 변경 금지.
- 설정 조회 실패 상태에서는 기본값으로 덮어쓰는 저장을 막는다. 수정 draft와 저장된 테마를 구분한다.

## 5. 모션

- 일반 화면 진입: alpha 0.65→1, 180ms 페이드. 위아래 이동을 추가하지 않는다.
- 출발: 기존 DepartureScreen의 로고·원형 그래픽·진행 표시, 3,320ms 안내와 480ms 퇴장. 안내는 실제 저장 완료 이후 표시한다.
- 완료 요약: 180ms 지연 후 720ms 등장, 초기 14dp 이동. 시스템 모션 배율을 따른다.
- 비용 폼/상세: animateContentSize로 내용 높이 변화 연결.
- HTML CSS의 blur·입자·모든 stagger 타이밍을 픽셀/프레임 단위로 복제한 상태는 아니다. 시안 전용 기록 블록 지연을 실제 앱 구현으로 간주하지 않는다.

## 6. 검증 및 남은 범위

2026-11-10 TAGO_Tablet(API 34, 2560×1600, 320dpi)에서 홈·준비·출발 로고·수동 구간·일시정지/재개·비용 추가/복귀·완료 확인/취소·완료 안내·정산 확인·설정·내역을 직접 조작했다. build, lint, JUnit 119건, 기기 테스트 26건을 통과했다. 상세 증거와 최초 기기 연결 중단/재실행은 [UI 재정렬 검수](ui-parity-2026-11-10.md)를 따른다. 이번 문서화 작업에서 테스트를 다시 실행한 것은 아니다.

실제 Pleos 차량 연결·시동 OFF·주행 차단, 휴대폰 QR 리더, TalkBack/큰 글꼴/작은 태블릿 전체 화면 검수는 남아 있다. 원본 HTML 샘플과 실제 Room 데이터 및 Android 시스템 영역 차이는 존재한다. 전체 화면의 픽셀 일치를 보증하지 않는다.
