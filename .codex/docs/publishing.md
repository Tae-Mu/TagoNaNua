# TAGO Compose 퍼블리싱

## 기준과 범위

2026-11-08 최신 HTML 시안(HD 프로젝트/preview)을 기준으로 작성했다. 원본 시안은 보존한다. 초기 기획서의 예상 유류비 방식과 달리 최신 시안은 주유/주차/톨비/기타 비용을 함께 표시한다. 이 변경은 화면 표현에만 적용하며 DB/정산 정책은 변경하지 않았다.

## 구성

- core/ui/theme: 기존 블루/네이비, SUIT 글꼴, 주간/야간 색상
- core/ui/component: 패널, 제목/차량 상태, 버튼, 입력, 요약 지표, 빈 상태, TAGO 로고
- feature/publishing: 화면별 Composable, 샘플 UI 모델, 화면 상태
- navigation/PublishingApp: 샘플 화면 전환, 뒤로가기, 화면 선택 및 상태 도구
- res: 기존 차량 이미지, 글꼴, 내비게이션/비용 VectorDrawable
- assets/asset-notices.txt: 원본 이미지 출처/글꼴 라이선스

## 화면

Home, Prepare, Departure, Trip, Resume, Complete, Costs, CostKind, Fuel, Expense, Settlement, Detail, History, Settings. 월/날짜 선택, 공통 확인창도 포함한다. Departure는 3,320ms 안내 후 480ms 퇴장하며 기록 화면 등장과 겹쳐 전환한다. 비용 입력의 등록/수정 완료는 진입 출처로 돌아간다. 기록에서 비용 추가 시 기록으로, 목록에서 수정 시 목록으로 복귀한다. 수정은 기존 샘플 값 입력과 완료 버튼을, 삭제는 대상 확인창을 제공한다. 데이터는 변경/영속 저장하지 않는다.

## 확인할 제약

이 작업은 네이티브 UI 초안이다. 기존 HTML의 세부 모션/모든 아이콘/각 화면의 정확한 간격까지 1:1 검수 완료한 결과는 아니다. 월 선택은 HTML 기준 3열 그리드·연도 이동·선택 요약·적용/취소로 구성했다. 일자 선택도 커스텀 달력이며 적용한 날짜를 폼에 표시한다. 조회 화면 오류와 입력 검증을 구분하고 구조형 로딩 샘플을 제공하며, 주요 목록에 빈 상태를 제공한다. 주행 샘플은 여행 화면 행동 비활성 표현이다. 실차 주행 제한이나 차량 권한은 구현하지 않는다.

Android Studio Compose Preview: LandscapePreview(1280×800), SmallTabletPreview(960×600). 실제 차량 디스플레이, 큰 글꼴, TalkBack, 야간 대비와 화면별 긴 문자열은 별도 렌더 검수가 필요하다.

## 검증

2026-11-09 사용자 승인 후 ADB로 TAGO_Tablet에 설치하고 실제 입력·탭·스크롤·화면 캡처로 비교했다. assembleDebug 및 lintDebug 성공. 화면별 수정과 검증 범위는 [직접 실행 QA 기록](publishing-qa-2026-11-09.md)을 따른다. 아래 11월 8일 기록은 당시의 제한이며, 전체 화면의 픽셀 일치나 실차 검증을 의미하지 않는다.

## 태블릿 표시 기준

태블릿 가로 화면을 기본으로 사용한다(sensorLandscape). 창 크기 변경은 허용하며 600dp 이상에서 왼쪽 내비게이션을 표시한다. 본문은 가용 폭을 채우고, 홈은 문구와 차량 이미지를 좌우로 배치한다. 좁은 분할 창에서는 세로 배치로 대응한다. 프리뷰의 dp 크기는 에뮬레이터 자체 크기를 변경하지 않는다.

## 2026-11-08 실제 태블릿 비교 1차

Android Studio에 TAGO_Tablet(API 34, Pixel Tablet) 검수 기기를 생성하고 앱을 실행했다. Running Devices 화면에서 홈을 직접 확인했다. 높은 홈 카드로 여행 목록이 잘리는 현상을 확인해 높이/내부 간격을 줄이고 재실행하여 목록 전체 표시를 확인했다. 보라색 기본 선택 칩은 TAGO tint로 변경한 뒤 실제 화면에서 확인했다. 여행 목록의 날짜/분리선/금액/상태를 HTML에 맞게 정렬했다.

여행 기록의 좌우 카드, 주유 입력 2열, 비용 요약/종류 소계/통합 목록도 코드에 반영했다. 이 화면들의 개별 실제 렌더 검수는 아직 남아 있다. 화면 제어 도구가 별도 Running Devices 창 클릭을 메인 IDE 창으로 보내는 문제가 있어 앱 내부 화면 전환 검증은 완료하지 못했다. 홈 외 화면을 검수 완료로 간주하지 않는다.


### 문구·모션 보정 (2026-11-08)
- 출발 준비의 이름/인원 입력을 출발 안내와 기록 제목에 전달. 빈 이름은 `새로운 여행`.
- HTML workflow.js 기준 3,320ms 출발 안내, 480ms 퇴장, 건너뛰기/뒤로가기 지원. 앱 로고 사용.
- 기록 주요 블록 350/620/730ms 지연 및 720ms 등장. 메뉴 전환 160ms 페이드, 스크롤 위치 화면별 초기화.
- 완료 안내 문구와 여행 종료 확인 문구 복원.
- 빌드/Lint 검증과 실제 기기 모션 검수는 별개. CSS의 blur·궤도 입자 및 모든 하위 요소의 개별 애니메이션은 아직 동일하지 않음.

## 검수사항 반영 (2026-11-09)

[20개 검수 항목의 반영 현황](publishing-audit-backlog-2026-11-09.md#검수사항-반영--2026-11-09)을 참고한다. 야간 토큰, 태블릿 가용 높이, 선택 여행 상세, 비용 수정 프리필·복귀, 공통 일자 선택, 확정 정산 요약, 빈 상태를 보정했다. 분담액은 UI fixture의 총액과 표시 인원을 사용한 샘플 표시이며 실제 정산 정책/DB 구현이 아니다. 검수 도구는 기본 접힘 상태다. 최신 APK 빌드와 lint를 통과하고 전용 태블릿에 설치했다. 원본 모션의 완전한 일치와 접근성/작은 태블릿 검수는 남아 있다.
