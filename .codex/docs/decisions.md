# 결정 기록

## 2026-11-09 — 결제액 방식을 현재 제품으로 채택

- 배경: 초기 기획은 주행거리·연비·유가로 예상 유류비를 계산했다. 최신 HTML 기준([html-api-spec](html-api-spec.md))은 사용자가 입력한 실제 결제 금액을 합산한다.
- 결정: 정산 총액은 정산에 포함한 FUEL/PARKING/TOLL/OTHER 실제 입력 금액의 합계다. 주유량(L)은 금액÷단가로 표시만 한다. 운전자 포함/제외를 지원하고 나머지는 정수 원으로 순서대로 배분한다. 계산 방식 식별자는 `payments-v1`이다.
- 이유: 사용자가 html-api-spec의 실제 결제액 합산 방식을 선택했다. 추정치는 실제 지출과 어긋나 분담 분쟁 소지가 있다.
- 영향:
  - 이전의 "예상 유류비·구간별 연비 합산·fuel_prices 입력·최종 총액 HALF_UP 반올림"은 새 정산의 계산 규칙이 아니다. 거리·연비는 기록 정보로만 남는다.
  - Room v2: v1 테이블은 유지하고 trips 컬럼과 새 테이블 4개를 추가한다. v1 정산·유가·구간은 삭제·변환하지 않고 "옛 추정 정산(legacy)"으로 읽기 전용 표시한다.
  - AGENTS.md와 역할 지침의 해당 문구를 개정했다.
- 미확인 사항: 새 구현의 테스트와 v1→v2 마이그레이션 실행은 사용자 요청에 따라 하지 않았다. html-api-spec의 설정, 잠시 멈춤, 삭제, PARKED 편집 제한, command_receipts는 미구현이다.

## 2026-11-09 — 이전 구현 테스트 결과의 지위

- 결정: 이전 추정 유류비 버전의 단위 107/107, 기기 21/21 결과는 이전 버전의 기록이며 새 구현의 근거로 쓰지 않는다.
- 이유: 계산·데이터·화면이 바뀌었고 새 구현에서는 `:app:assembleDebug`만 실행했다.

## 2026-11-08 — 문서 보관함

- 결정: 프로젝트 .codex/docs/를 옵시디언 보관함이자 상세 문서 원본으로 사용합니다.
- 이유: Obsidian과 Codex가 같은 Markdown을 읽어 문서 복제를 줄입니다.
- 영향: 공통 작업 지침은 AGENTS.md, 역할 지침은 .codex/agents에 유지합니다. 별도 MCP는 사용하지 않습니다.

## 기존 합의 — 초기 앱 구성

- Kotlin, Compose, Room, Pleos Vehicle SDK를 사용합니다.
- app 단일 모듈로 시작하고 차량 데이터 인터페이스로 실제·샘플 구현을 나눕니다.
- Room이 유일한 DB이며 초기에는 별도 서버·MySQL을 사용하지 않습니다.
- 첫 QR 공유는 정산 요약 텍스트입니다.
- 역할 문서는 자동 병렬 실행 설정이 아닙니다.
