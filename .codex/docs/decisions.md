# 결정 기록

## 2026-11-12 — 구간별 유류비 방식으로 정산 규칙 변경 (구현됨, 일부 미검증)

- 상태: 사용자 확정(2026-11-12). 도메인 계산기(`FuelSettlementCalculator`)와 JVM 단위 테스트는 구현·통과했고 AGENTS.md·README·planning·architecture·database·testing에 반영했다. 저장(Room v5)·차량 수집·화면·확정 스냅샷도 구현했고, 2026-11-12에 `:app` 빌드·단위 테스트 158건·Lint·에뮬레이터 기기 테스트 49건(저장·확정 롤백·불변 트리거·화면 렌더링 포함)을 통과했다. 실차 동작은 검증하지 않았다(실차 없음). 새 여행만 `fuel-segments-v2`이며 기존은 `payments-v1`이다. 아래 "미확정"은 구현하면서 정한다.
- 배경: 사용자가 2026-11-09 결정("정산 총액 = 입력한 결제 금액의 합")이 의도와 다르다고 밝혔다. 의도한 앱은 구간별 유류비를 계산하고 주유비 외 입력 금액을 더해 인원수로 나눈다.
- 결정(사용자 확정):
  - 총액 = Σ(구간별 유류비) + 기타 비용(PARKING/TOLL/OTHER 입력 금액). 분담은 총액 ÷ 인원(정수 원, 나머지 1원씩 순서 배분은 기존 규칙 유지).
  - 구간 사용량: 내연은 거리 × 연비(L/100km), 전기는 거리 ÷ 효율(km/kWh). 시작·종료 시점 스냅샷의 차이로 구한다.
  - 단가: 여행 중 첫 주유의 입력 단가(L당 가격)를 그 이전 구간과 다음 주유 전까지 적용한다. 두 번째 이후 주유는 그 주유의 입력 단가를 이후 구간에 적용한다. 단가는 주유 폼 입력값이며 SDK 연료량(L)이나 탱크 용량은 쓰지 않는다.
  - 구간 경계: 여행 시작·종료, 주유 감지(연료 % 증가, `Fuel.registerFuelPercent`), P단(`Gear.registerGearSelection`, GEAR_PARK) 진입 후 주행거리 변화 없이 **2분 이상** 정차. 시동 OFF 공개 이벤트는 SDK에 없다.
  - `Odometer.getTripCurrentDrivingDistance` 리셋(C)은 관찰용으로만 기록한다. 리셋 조건이 확인된 뒤 경계 신호로 승격하며, 정산 계산은 C 없이도 완성되어야 한다. 가까운 시각의 중복 경계는 하나로 합친다.
  - 계산은 여행 종료 후 한 번에 수행한다. 여행 중 비용을 입력하면 그 시점의 미리보기를 보여줄 수 있다.
- 이유: 영수증 합계가 아니라 이동에 쓴 연료를 구간별로 반영하려는 제품 의도. 주유 때마다 단가가 바뀌므로 주유는 필수 경계다. 비용 입력 시점 대신 연료 % 증가로 감지해 사용자가 주유 직후 입력해야 하는 부담을 없앤다.
- 영향(구현 시): AGENTS.md "데이터 및 계산"·"프로젝트 기준" 문구, planning.md 확정된 정책, architecture.md 정산 계산, database.md(구간별 계산 결과·주유 이벤트·새 `calculationVersion`) 개정. 이미 확정된 `payments-v1` 정산은 수정·재계산하지 않고 그대로 읽기 전용으로 둔다. 연비·연료 원본값은 정산 총액이 아니라 구간별 계산의 입력이므로 이전의 "연비는 정산에 쓰지 않는다" 원칙이 바뀐다. 누적 평균을 구간 평균으로 취급하지 않는 원칙은 유지하며, 스냅샷 차이로 구간값을 구한다.
- 추가 확정(사용자, 2026-11-12):
  - 주유 감지 임계값: 연료 %가 경사·출렁임 이상으로 오른 경우만 주유로 본다. 초기값은 **5%**(설정 상수)다. 사용자 제시 30~40% → 10% → 5% 순으로 낮췄다. 낮출수록 소량 주유 누락은 줄지만 경사·출렁임에 의한 오감지가 늘 수 있고, 연료 %가 정수라 경계값 오차가 있다. 실차 노이즈 크기는 미확인이며 오감지·누락은 해소 수단(미확정 항목)으로 처리한다.
  - 감지된 주유 이벤트 수와 입력한 FUEL 비용 수가 다르면 여행을 종료할 수 없다.
  - 여행 중 주유가 없으면 단가를 직접 입력받되 입력하지 않아도 정산을 막지 않는다. 이 경우 유류비는 합계에 포함하지 않으며 화면에 "유류비 미포함"으로 표시한다.
  - 반올림은 합계에서 한 번만 한다(구간별 반올림 없음). 방식은 HALF_UP.
  - "단가 직접 입력, 비워 두면 유류비를 빼고 정산"으로 확정(사용자 확인).
  - 주유 이벤트와 FUEL 비용의 짝짓기는 **입력 순서**(방법 A)다. N번째로 입력한 FUEL 비용은 시간순 N번째 감지 주유와 짝이 된다.
  - 비용 입력 화면에 작은 경고문 하나를 둔다. 문구(초안): "주유 비용은 주유한 순서대로 입력해 주세요. 순서가 바뀌면 구간별 단가가 달라져 금액이 달라질 수 있어요." 작은 보조 문구 크기로 표시하고 오류·차단 스타일을 쓰지 않는다. 짝짓기 규칙이 구현될 때 함께 추가한다.
  - 종료가 막힌 사용자를 위한 해소 수단은 둘 다 둔다: ① 감지된 이벤트를 "주유 아님"으로 제외, ② 감지되지 않은 주유 비용에 "감지 안 됨" 표시(해당 비용을 순서 짝짓기에서 제외). 종료 조건은 제외 처리한 이벤트를 뺀 감지 이벤트마다 짝이 된 FUEL 비용이 있는 것이다.
- 미확정:
  - **앱 생명주기**: 시동 OFF 후 재시동했을 때 앱이 자동으로 실행·유지되는지 알 수 없다(2026-11-12 기준 확인 안 됨). 앱이 실행 중이 아니면 기어·연료·거리 리스너 이벤트를 받지 못한다. 공개 시동 이벤트도 SDK에 없다. 제안(구현 시): 리스너 갱신마다 스냅샷을 Room에 저장하고, 앱이 다시 시작되면 저장된 마지막 값과 현재 차량 값을 비교해 구간 경계·주유(연료 % 증가)를 복원한다. 복원할 수 없는 구간은 "기록 공백"으로 표시하고 유류비 계산에서 제외한다. 임의 보정하지 않는다.
  - 에뮬레이터 조사(2026-11-12, 문서 열람만, 직접 실행 안 함): Pleos Connect Emulator v2.1.0 이상의 Virtual Console(`adb forward tcp:8088 tcp:8088` 후 `http://127.0.0.1:8088/`)이 Motion(기어·브레이크·주행거리)과 Energy(주행 가능 거리·배터리·충전) 등을 조작한다고 한다. 시동(ignition) 사이클, 내연 연료 %, 연비, 앱 자동 실행은 확인된 항목에 없다. AAOS `IGNITION_STATE`가 읽기 가능 속성으로 안내되어 있다는 검색 요약이 있으나 표를 직접 확인하지 못했고, Pleos SDK에 없는 속성을 직접 쓰려면 기술지원팀 검토를 받으라는 안내가 있다.
  - 연비를 못 받은 구간의 처리. 제안: 여행 시작·주유 직전·종료 시점의 연비·거리 스냅샷으로 주유 구간 단위 사용량을 구하고(측정값의 뺄셈), 중간 구간은 그 합계 안에서 거리 비례로 나눈다. 주유 구간 경계 스냅샷이 없으면 그 구간 유류비를 제외하고 "유류비 미포함"으로 표시한다. 사용자 확인 대기.
  - 새 `calculationVersion` 이름과 전기차 단가 단위(kWh당).
- 실차 검증 필요(잠정 가정): 주유 이후/누적 연비가 공회전 연료를 포함하는지, 시동 때 초기화되는지, 연비 API가 실제 값을 반환하는지(에뮬레이터는 8개 모두 지원하지 않음), C의 리셋 조건, 시동 OFF 시 앱 실행 지속 여부.

## 2026-11-09 — 결제액 방식을 현재 제품으로 채택

- 배경: 초기 기획은 주행거리·연비·유가로 예상 유류비를 계산했다. 최신 HTML 기준([html-api-spec](html-api-spec.md))은 사용자가 입력한 실제 결제 금액을 합산한다.
- 결정: 정산 총액은 정산에 포함한 FUEL/PARKING/TOLL/OTHER 실제 입력 금액의 합계다. 주유량(L)은 금액÷단가로 표시만 한다. 운전자 포함/제외를 지원하고 나머지는 정수 원으로 순서대로 배분한다. 계산 방식 식별자는 `payments-v1`이다.
- 이유: 사용자가 html-api-spec의 실제 결제액 합산 방식을 선택했다. 추정치는 실제 지출과 어긋나 분담 분쟁 소지가 있다.
- 영향:
  - 이전의 "예상 유류비·구간별 연비 합산·fuel_prices 입력·최종 총액 HALF_UP 반올림"은 새 정산의 계산 규칙이 아니다. 거리·연비는 기록 정보로만 남는다.
  - Room v2: v1 테이블은 유지하고 trips 컬럼과 새 테이블 4개를 추가한다. v1 정산·유가·구간은 삭제·변환하지 않고 "옛 추정 정산(legacy)"으로 읽기 전용 표시한다.
  - AGENTS.md와 역할 지침의 해당 문구를 개정했다.
- 미확인 사항: 새 구현의 테스트와 v1→v2 마이그레이션 실행은 사용자 요청에 따라 하지 않았다. html-api-spec의 설정, 잠시 멈춤, 삭제, PARKED 편집 제한, command_receipts는 미구현이다.
