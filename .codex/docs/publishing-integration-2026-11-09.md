# 퍼블리싱 UI와 로컬 기능 연결

작업 브랜치: `loren_dev`. 대상은 실제 앱 `com.gatita`이다. 별도 샘플 앱 `com.gatita.publishing`과 구분한다.

## 구조

`MainActivity → AppNavHost → ConnectedShell → 기능별 Route/ViewModel → 기존 UseCase → Repository → Room`.

- `PublishingApp`과 고정 샘플 화면은 Compose Preview용으로 보존한다. 실제 런처에서는 호출하지 않는다.
- 기존 퍼블리싱의 TAGO 테마·폰트·로고·차량 이미지·패널·버튼·비용 아이콘·월/일 선택·출발 모션을 기능 화면에서 재사용한다.
- 실제 화면은 기존 `HomeViewModel`, `TripViewModel`, `CostFormViewModel`, `SettlementViewModel`, `HistoryViewModel`, `ResultViewModel`을 구독한다. UI가 DAO를 호출하거나 샘플 총액을 실제 결과로 표시하지 않는다.
- 앱 식별자와 기존 Room DB를 유지한다. 스키마 변경이나 데이터 초기화는 없다.

## 연결한 흐름

| 화면 | 연결 내용 |
|---|---|
| 홈 / 출발 준비 | Room의 진행 중 여행 및 미확정 목록. 이름·출발 누적거리·인원·본인 포함 정책을 StartTripCommand에 전달. 저장 성공 이벤트 뒤 앱 로고 안내, 실제 여행 ID로 이동 |
| 여행 기록 | 저장한 여행·구간·비용 합계 표시. 선택 입력한 구간은 기존 SaveSegmentUseCase 사용. 비용 요약 카드로 관리 화면 진입 |
| 비용 종류 / 입력 | 주유·주차·톨비·기타. 결제액, 주유 단가·일자, 장소/설명 선택 입력. 주유량은 FuelLiters 도메인 함수를 이용한 표시값 |
| 비용 관리 | 실제 목록·종류별 합계·포함/제외 합계. 수정 프리필·삭제 확인. 저장 실패 시 입력 유지, 성공 시 호출한 화면으로 pop. 기록에서 추가하면 기록으로, 관리 화면에서 수정하면 관리 화면으로 복귀 |
| 여행 완료 | CompleteTripUseCase 성공 후 완료 화면. 나중에 정산 또는 정산으로 이동. 구간과 비용이 없는 여행은 기존 빈 여행 닫기 사용 |
| 정산 | 도메인 미리보기·인원/운전자 정책 저장·개인별 명세·확정 확인. 확인 당시 revision/requestId 및 기존 SubmitGuard 유지 |
| 확정 결과 | 저장된 스냅샷 조회, 수정 행동 없음. 실제 요약 텍스트 복사와 QR 표시. 옛 추정 정산은 기존 LegacySettlementCard로 구분 |
| 여행 내역 | Room 월별 조회·필터·월 통계. 공통 월 선택에서 적용한 월 전달. 같은 월/필터 재선택 시 불필요한 로딩 고정 방지 |
| 설정 | 실제 화면 테마 전환(현재 앱 세션)과 저장/연결 안내. 미구현 설정에 저장 성공을 표시하지 않음 |

## 실제 기능과 시안의 차이

- Pleos SDK가 없으므로 `정차 중` / `시동 OFF 자동 저장`으로 표시하지 않는다. 실제 화면에 `수동 기록`을 표시하고 구간은 선택 입력한다. 임의 차량명·30km·149,600원 샘플은 실제 데이터 화면에 쓰지 않는다.
- 진행 중 여행은 Room에서 복구한다. 별도 PAUSED 상태나 시동 감지 기능을 추가하지 않았다.
- 일반 여행 삭제·영구 설정 저장/초기화·차량 연결·자동 톨비 수집은 기존 backend에 없어 연결 완료 범위가 아니다. 빈 여행 닫기와 비용 삭제만 실제 기능이다.
- 설정 테마는 세션 상태다. 앱 종료 후에도 유지되는 영구 설정으로 안내하지 않는다.
- 일반 폼과 정산이 실제 데이터에 연결됐지만 원본 HTML의 모든 간격/모션과 픽셀 단위 일치를 의미하지 않는다.

## 검증

- `assembleDebug`와 `lintDebug` 실행. Lint에서 기존 모델의 `LocalDate.EPOCH`가 minSdk 29와 맞지 않음을 발견해 동일 날짜의 `LocalDate.ofEpochDay(0)`으로 변경했다.
- 기존 테스트 스위트는 결제액 방식 이전 인터페이스 기준이며 이번에 단위/기기 테스트 스위트를 실행한 것으로 보고하지 않는다. 직접 조작 검수는 전용 TAGO 태블릿(emulator-5556)에서 진행한다.
- 스크린샷·조작 결과: `app/build/visual-review/2026-11-09-connected/` (Git 제외).


### 직접 조작 결과

검수용 여행 `TAGO-QA-1109`를 생성해 실제 Room에 저장했다. 데이터 초기화 없이 APK를 업데이트하고 프로세스를 종료·재실행했다.

- 여행 이름, 인원 4명 저장 및 시작 성공 후 로고 안내 → 기록 이동 확인.
- 주차 3,000원 저장 후 기록 복귀, 앱 재실행 후 여행과 비용 복구 확인.
- 주유 50,000원 / 1,890원/L → 도메인 주유량 26.455L, 합계 53,000원 확인.
- 주차 5,000원으로 수정 → 합계 55,000원, 주유 제외 → 포함액 5,000원, 주유 재포함 → 55,000원 확인.
- 주차 삭제 후 톨비 5,400원과 기타 1,000원 등록. 기타 설명 저장 및 해당 비용 삭제 확인. 최종 총액 55,400원.
- 여행 완료 성공 화면 → 정산 이동. 운전자 제외 시 0 / 18,467 / 18,467 / 18,466원, 합계 55,400원 확인.
- 정산 확정 후 스냅샷 조회 및 요약 복사 확인. APK 업데이트·앱 재실행 이후 같은 여행/금액 조회 확인.
- 실제 렌더에서 발견한 QR 과대 확장(`fillMaxWidth` 뒤 `widthIn`의 순서 문제)을 수정해 320dp 이내로 제한했다. QR 생성·표시만 확인했으며 휴대폰 리더 스캔을 확인한 것은 아니다.
- 실제 탐색에서 발견한 사이드 메뉴의 하위 화면 재복원 문제를 수정했다. 최상위 메뉴는 해당 목록으로 이동하며 상세 화면의 뒤로가기와 구분한다.

초기 자동 조작의 잘못된 선택자(주차비/주차), 화면 아래 체크박스 좌표, 클릭할 수 없는 QR 제목 선택에서 발생한 실패는 해당 조작을 수정해 재실행했다. 이를 앱 기능 성공으로 세지 않았다. 메뉴 복귀 문제와 QR 크기는 실제 UI 결함으로 수정했다.


최종 재검수 6개 확인 항목 통과: 업데이트·재실행 뒤 확정 내역, 320dp QR·요약 복사, 10월 필터 적용, 11월 내역 복원, 야간 테마 적용, 정산 목록의 저장된 확정 금액. 화면별 실제 조작 결과는 `final-results.json`에 기록했다. 주유량 미리보기는 금액·단가 입력 파서를 통과한 값만 표시하도록 정리했고, 최종 빌드·Lint를 다시 실행했다.

남은 검증: 작은 화면·큰 글꼴·TalkBack·빠른 연속 조작·DB 실패 주입·마이그레이션·외부 QR 리더. 현재 확인된 실제 저장 흐름을 이 항목들의 통과로 확대하지 않는다.

## 후속 전체 연결·QA 진행 (2026-11-09)

사용자가 전체 연결과 QA/엣지케이스 테스트를 명시적으로 요청하여 이전의 테스트 미실행 방침을 변경했다. 후속 작업을 완료했으며 [전체 연결 검수](full-integration-qa-2026-11-09.md)에 최종 결과와 외부 미연결 범위를 기록했다.

- Room v3 설정 저장: 표시 이름, 운전자 포함 기본값, 시스템/주간/야간 모드. 설정 초기화는 여행을 삭제하지 않는다. 저장 실패 시 입력 및 기존 설정 보존, 읽기 실패 시 덮어쓰기 차단.
- Room v4 일시정지: `trip_sessions`에 수동 일시정지 시각 저장. 기존 IN_PROGRESS 단일 여행 제약 유지, 같은 여행 재개, 완료된 여행의 일시정지 거부. 차량 시동 감지가 아니다.
- 여행 내역의 목록 삭제: 여행·정산 목록에서 숨긴다. 확정 및 legacy 원본은 불변 보관하고 확인창에 알린다. 실제 영구 삭제와 구분한다. 진행 중 여행은 삭제 대상에서 제외하고 기존 빈 여행 닫기를 제공한다.
- 비용 수정에 로드한 revision을 전달해 오래된 편집 화면의 덮어쓰기를 차단한다. 입력은 보존하고 ‘최신 내용 다시 불러오기’를 제공한다.
- 단위 테스트: 이전 화면 API를 현재 결제액 방식에 맞춰 갱신. 기존 legacy 계산 회귀 검증은 유지했다.
- 기기 테스트: 실제 TAGO_Tablet(emulator-5556, Android 14), 별도 테스트 DB만 생성·삭제한다. 테스트 코드에서 `gatita.db`를 직접 지우지 않으나 Gradle UTP의 APK 제거로 이전 QA 데이터가 초기화된 점을 확인했다. 이후 직접 계측 실행으로 전환했다.
- 실제 차량 자동 거리·연비·시동/PARKED 신호 및 자동 톨비 결제 수집은 SDK/공급자 구현이 없으므로 연결하지 않는다. 수동 입력을 실제 차량 측정으로 표시하지 않는다.
