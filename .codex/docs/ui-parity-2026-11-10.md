# HTML → 실제 앱 UI 재정렬 (2026-11-10)

기준: 로컬 `HD 프로젝트/preview` HTML, 기존 publishing 화면 컴포넌트. 실제 앱은 `com.gatita`, TAGO_Tablet 2560×1600 / 320dpi.

## 반영
- 공통 헤더: 돌아가기 때문에 생기던 별도 상단 행 제거, 제목/설명/보조 액션 정렬. 수동 기록 배지는 필요한 화면에만 표시.
- SUIT를 모든 Material 텍스트 스타일에 적용. 입력 테두리·배경, 인원 버튼, 필터 칩 모양 통일. 화면 진입은 위치 이동 없는 짧은 페이드.
- 홈: 시안의 본문과 출발 안내, 하단 3단계 안내 복원. 전체 정산 버튼은 정산 목록으로 연결.
- 출발 준비: 단계 표시, 좌측 입력/우측 차량 안내 2열 복원. 실제 기능의 수동 계기판 입력은 유지.
- 여행 기록: 큰 거리와 작은 단위, 가로 구간 카드. 일시정지는 별도 기록 요약 카드와 재개/비용/완료 액션으로 구성.
- 여행 종료: 커스텀 확인창과 중앙 완료 요약/정산 액션 복원.
- 비용: 상세 정보 펼침을 카드형으로 정리. 기존 비용 등록/복귀 경로 유지.
- 내역: 월 선택과 월별 통계를 같은 상단 행에 배치.
- 정산: 하단 안내와 우측 확정 버튼 정렬.
- 설정: 프로필 요약 및 2열 설정 카드 복원.

- 테스트 전용 여행 `UI-QA-1110`, 주유 50,000원/1,890원 입력. 사용자 기록 삭제 없음.
- 스크린샷: `app/build/visual-review/2026-11-10-parity/` (빌드 산출물, Git 제외).

## 차이와 제약
- HTML 시안의 가상 차량 자동 연결/시동 기록 문구는 실제 미구현 기능으로 표시하지 않는다. 수동 기록과 기기 저장을 명시한다.
- HTML 샘플 데이터와 실제 Room 데이터 차이, Android 시스템 바/작업 표시줄에 따른 가용 높이 차이는 유지된다.
- 태블릿 기준 검수이며 휴대폰·실차 검증 결과가 아니다. 픽셀 단위 완전 일치를 의미하지 않는다.

## 후속 정책 수정: 거리 입력 제거

사용자 지시에 따라 출발 계기판/구간 종료 거리/연비 수동 입력과 구간 저장 버튼을 제거했다. 여행 시작은 VehicleDataSource 성공값(PLEOS)만 사용한다. SDK 미연결·실패·시간 초과·샘플 반환 시 새 여행을 생성하지 않으며 0km로 대체하지 않는다. 현재 실제 어댑터가 없어 연결 전 시작은 보류된다. 기존 기록은 유지한다. 위 수동 구간 QA는 수정 전의 이력이다.

후속 검증: assembleDebug·lintDebug·assembleDebugAndroidTest 성공. JUnit 120건 통과(차량 측정값 시작, 미연결 시 생성 방지, 샘플값 사용 방지 포함).
기기 계측 26건 통과(`OK (26 tests)`). 출발 준비의 거리 입력 부재를 Compose 테스트로 확인했다.

## 최신 HTML 재비교 — 비용 입력 중심 후속 수정

기준: 2026-11-10 localhost 시안을 새로고침한 실제 화면. 이전 열린 탭의 구버전과 혼동하지 않도록 비용 선택/주유 입력 화면을 다시 확인했다.

- 비용 선택: 가로 4개 카드를 HTML과 같은 2×2로 변경. 종류별 설명, 우측 화살표, 하단 선택 입력 안내를 복원했다.
- 비용 입력: 페이지 부제목과 상단 복귀 링크, 외부 입력 라벨, 32sp 금액/단가, 별도 단위 표시, 주유량 좌우 정렬을 적용했다. 주유 폼의 불필요한 종류 칩은 제거했다.
- 상세 정보: 선택 배지와 펼침 버튼 배경을 분리했다. 주차 장소·톨게이트/구간·기타 내용은 기존 선택 입력 기능을 유지한다.
- 비용 내역: 종류별 합계 카드의 아이콘과 금액을 가로 정렬했다.
- 홈: 큰 제목/본문 비율과 차량 설명 영역을 보완했다. 미연결 차량 이름을 임의로 표시하지 않는다.
- 여행 내역: 날짜를 일 숫자 + 월 형식으로 정리했다. 공통 페이지 부제목은 16sp로 맞췄다.

검증: assembleDebug, testDebugUnitTest(120개), lintDebug, assembleDebugAndroidTest 성공. emulator-5556에서 직접 instrumentation 26개 통과. 최초 기기 실행은 홈의 동일 문구 2개로 단일 노드 assertion이 실패했으며, 중복 설명을 정리한 후 전체 재실행해 통과했다.

실제 태블릿에서 비용 선택, 주유 입력, 50,000원/1,890원 입력 시 약 26.455L 표시, 상세 펼침을 확인했다. 기존 여행에 저장하지 않고 입력 초안으로 확인했다. 증거: app/build/visual-review/2026-11-10-html/ (빌드 산출물, 버전 관리 제외).

범위: 이번 수정은 확인한 비용 화면과 공통 서식 차이를 줄인 작업이다. 모든 화면의 픽셀 일치나 실제 SDK 연결 완료를 뜻하지 않는다. 거리 수동 입력 제거, SDK 미연결 시 새 여행 시작 보류, 기존 기록 보존 정책을 유지한다.

### 인터랙션 후속 보정

- HTML workflow.css의 :active scale(.975)/140ms를 공통 Action·ActionButton 및 비용 종류 카드에 적용. 레이아웃/터치 영역은 유지하고 렌더 크기만 변경한다. 비활성 버튼은 축소하지 않는다.
- NavHost 기본 전환과 화면 자체 페이드의 중복을 제거. 공통 화면은 HTML navigation-fade와 같이 .65→1/160ms. 비용 종류 선택 등 같은 route 안 제목 변경에도 페이드가 재실행된다. 사이드 메뉴 전환에는 세로 이동을 넣지 않는다.
- 주유 상세 펼침/접힘은 fade+height 애니메이션으로 변경하고 화살표는 220ms 회전한다. 카드 높이는 기본 spring 대신 240ms ease-out으로 맞춘다. Compose 애니메이션은 시스템 모션 배율을 따른다.
- assembleDebug/testDebugUnitTest/lintDebug/assembleDebugAndroidTest 성공, 직접 기기 테스트 26개 통과. 출발 로고 모션은 이번 수정 범위에 포함하지 않았다. SDK 미연결로 신규 여행 시작을 차단하는 정책을 유지한다.

### 모션 속도 조정 (사용자 피드백)

느리게 느껴진다는 피드백에 따라 HTML 원본 시간보다 빠르게 조정했다. 상세 영역 AnimatedVisibility와 부모 animateContentSize가 중첩되어 높이를 추적하던 구성을 제거하고 내부 펼침만 유지했다. 펼침 160ms/접힘 140ms, 화살표 160ms, 버튼 누름 70ms/복원 110ms, 페이지 페이드 .85→1/100ms. OS 모션 설정은 변경하지 않았다. assembleDebug 및 lintDebug 성공. 데이터 처리·SDK 정책은 변경하지 않았다.
