# Backend — 로컬 데이터 및 도메인

이 프로젝트의 backend는 서버가 아니라 데이터와 정산 규칙 담당이다. MySQL, REST 서버, 인증 기능을 임의로 추가하지 않는다.

## 담당 범위

domain/model, repository, calculator, usecase 및 data/local, mapper, repository와 app/schemas. 차량 조회 규약은 vehicle 담당과 합의한다.

## 구현 규칙

- Entity, DAO, Repository 구현과 도메인 모델의 역할을 분리한다.
- 여행 상태와 허용 전이를 정의하고 진행 중 여행 및 구간 순번의 일관성을 보장한다.
- 중복 이벤트나 중복 확정에도 같은 기록이 여러 번 만들어지지 않도록 트랜잭션과 제약을 설계한다.
- 비용 금액(1~10,000,000원)·종류별 필드·단가·인원(1~8)을 검증하고, 음수 거리·감소한 누적거리·0 이하 연비는 기록 구간 입력으로 거부한다.
- 정산 총액은 포함된 실제 결제 금액의 합이다. 연비 집계 기준은 기록 정보로 보존하되 정산 계산에 쓰지 않고, 측정 실패를 0으로 저장하지 않는다.
- 확정 시 제외 비용을 포함한 비용 복사본, 인원·운전자 정책, 사람별 분담액을 함께 저장한다. DB를 바꾸면 v1 데이터를 보존하는 마이그레이션을 쓴다.

## 완료 기준

정산 합계 및 분담액 불변식, 나머지 배분, 재실행 복구와 필요한 Room 마이그레이션을 검증하고 결과를 보고한다. 실행하지 않은 검증은 미실행으로 명시한다.

## 옵시디언 문서 연계

- 루트 AGENTS.md의 보관함 및 문서 경로 설정을 확인한다.
- 관련 원본: DB 설계·정산 규칙·테스트 전략·보안 규칙. 실제 파일 경로가 연결된 항목을 읽고 적용한다.
- 상세 정책을 이 역할 파일에 복제하지 않고 .codex/docs/의 원본에서 관리한다. 연결되지 않은 문서는 확인했다고 보고하지 않는다.
