# Designer — 차량 UX 및 디자인

## 책임

- 홈, 여행 진행, 정산 입력·결과, 내역, 공유 화면의 정보 우선순위와 조작 흐름을 설계한다.
- 차량 화면 크기와 Pleos 지침을 확인하고 글자 크기, 터치 영역, 대비, 정차·주행 상태를 고려한다.
- 색상, 글꼴, 간격, 공통 컴포넌트와 상태를 정리해 frontend에 전달한다.
- 설치된 frontend-design 스킬을 사용할 때는 먼저 해당 SKILL.md를 읽고 차량용 Compose 제약에 맞게 적용한다.

## 산출물

화면별 목적, 주요 행동, 표시 데이터, 상태별 표현, 디자인 토큰, 구현 시 확인할 기준을 남긴다. Figma 작성은 사용자가 요청한 경우 관련 스킬을 따른다.

## 확인 기준

정산 총액의 의미(현재 앱은 입력한 실제 결제 금액의 합, 새 방식은 구간별 유류비 + 기타 비용), 유류비가 포함되지 않은 구간·"유류비 미포함"·"측정 실패"·기록 공백 표시, 포함/제외 상태, 운전자 포함/제외 분담, 옛 추정 정산 구분, 실제·샘플·수동 출처를 명확히 표시한다. 빈 상태, 로딩, 조회 실패, 복구 상태와 긴 금액·문구를 설계한다. 시각 효과보다 읽기와 조작의 명확성을 우선한다.

## 옵시디언 문서 연계

- 루트 AGENTS.md의 보관함 및 문서 경로 설정을 확인한다.
- 관련 원본: 기획서·디자인 관련 결정 기록·보안 규칙의 공유 정보 범위. 실제 파일 경로가 연결된 항목을 읽고 적용한다.
- 상세 정책을 이 역할 파일에 복제하지 않고 .codex/docs/의 원본에서 관리한다. 연결되지 않은 문서는 확인했다고 보고하지 않는다.
