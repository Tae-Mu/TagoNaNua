# CI/CD — 빌드 및 검증 자동화

## 담당 범위

Gradle 설정·Wrapper, 라이브러리 버전, .github/workflows, 빌드 관련 .gitignore 및 실행 안내. 앱 배포는 사용자가 요청한 범위에서 수행한다.

## 구현 규칙

- 먼저 현재 빌드 설정과 로컬 JDK·Android SDK·Pleos 의존성 조건을 확인한다.
- 공식 호환 정보를 확인해 버전을 선택하고 버전 설정을 한곳에서 관리한다.
- Android 프로젝트가 준비된 뒤 실제 존재하는 Gradle 작업으로 CI를 구성한다.
- 초기 CI는 단위 테스트, Android Lint, debug APK 빌드를 중심으로 구성한다. 기기 테스트는 실행 환경을 확보한 경우 추가한다.
- SDK 저장소 인증이 필요한 경우 비밀값을 CI secrets로 주입한다. 키를 로그나 저장소에 노출하지 않는다.
- 서명된 배포 빌드와 스토어 제출은 별도 작업으로 다룬다. 릴리스 완료를 APK 빌드 성공과 혼동하지 않는다.

## 완료 기준

실행 명령, JDK·SDK 조건, 검증 결과, 생성 아티팩트와 CI에서 미확인인 항목을 보고한다. 현재처럼 빌드 파일이 없는 단계에는 통과할 수 없는 워크플로를 미리 추가하지 않는다.

## 옵시디언 문서 연계

- 루트 AGENTS.md의 보관함 및 문서 경로 설정을 확인한다.
- 관련 원본: 테스트 전략·보안 규칙·빌드 및 배포 관련 결정 기록. 실제 파일 경로가 연결된 항목을 읽고 적용한다.
- 상세 정책을 이 역할 파일에 복제하지 않고 .codex/docs/의 원본에서 관리한다. 연결되지 않은 문서는 확인했다고 보고하지 않는다.
